# 선택형 Gemini 발주 해설

`feat/web-deploy`의 `e50c1e4`에서 분기한 `feat/llm-briefing`입니다. 발주 페이지에 계산 기반 기본 설명과 **AI 해설 생성** 버튼을 추가합니다. 예측·발주 엔진·DB·로그인 코드는 변경하지 않습니다.

## Vercel 설정

Vercel 프로젝트의 Environment Variables에 설정한 뒤 다시 배포합니다. 키를 코드나 GitHub에 올리지 마세요.

| 변수 | 설정 |
| --- | --- |
| `GEMINI_API_KEY` | 본인의 Gemini 키. 서버 전용이며 `NEXT_PUBLIC_`을 붙이지 않습니다. |
| `GEMINI_MODEL` | `gemini-flash-lite-latest`. 생략해도 이 모델입니다. 기존 다른 값이 있으면 변경해야 합니다. |
| `GEMINI_ENABLED` | `0`이면 AI 호출을 끕니다. 기본 설명은 계속 표시합니다. |

브랜치 push만으로 운영 배포의 환경 변수가 바뀌지는 않습니다. 함수 실행 제한은 서버 호출 시간에 맞춰 확인하세요 (`maxDuration=15`).

## 동작과 한계

- 버튼 클릭 시에만 호출합니다. 키가 없거나 AI가 꺼져 있으면 외부 호출 없이 기본 설명을 반환합니다.
- 현재 화면 엔진 결과의 실제 입력 발주량·설정으로 요약을 구성합니다. 입고 전 부족과 사용기한 문제 등을 우선해 최대 다섯 품목을 보냅니다. 원본 CSV 전체를 전송하지 않습니다.
- 로그인 매장과 요청 매장이 같은지 검증합니다. 설명 전용 입력이며 서버에서 엔진을 다시 계산하거나 발주서를 저장하지 않습니다.
- 수량·비용·입고일은 계산값으로 별도 표시합니다. AI는 행동 설명만 작성합니다. 형식·품목 ID·본문 숫자를 검증하고 실패하면 기본 설명을 표시합니다. 의미적 정확성 전체를 보장하는 검증은 아닙니다.
- 서버 대기 최대 십 초, 브라우저 최대 십사 초입니다. 자동 재시도나 모델 순환 호출은 하지 않습니다.
- 연속 호출 이십 초 간격, 같은 조건의 성공 결과 오 분 캐시, 프로세스당 동시 요청 두 개·캐시 최대 백 개입니다. Vercel 인스턴스마다 별도이므로 프로젝트 전체 쿼터를 보장하지 않습니다.
- 입력 수량·날짜·설정이 바뀌면 이전 AI 해설을 숨깁니다. `계산 기반 기본 설명`과 `Gemini AI 해설`을 구분합니다.
- 예상 폐기는 해당 입고 주기의 기존 재고와 추가 발주 증가분을 구분합니다. 보관·품질·조리 폐기 감소 효과를 주장하지 않습니다.

## 실제 호출 확인 — 2026-10-31

테스트용 발주 요약으로 실제 Google API 호출과 앱 응답 검증을 확인했습니다. 첫 비교 결과가 테스트 출력에 남지 않아 비교를 한 차례 더 실행했습니다. 아래는 기록된 결과입니다. 키와 응답 원문은 기록하지 않았습니다.

| 모델 | 결과 | 시간 |
| --- | --- | --- |
| `gemini-flash-latest` | 앞선 로컬 화면 호출 HTTP 503, 다음 호출 시간 초과. 기본 설명 복귀 확인 | 약 칠 초 / 십 초 |
| `gemini-flash-lite-latest` | HTTP 200, 완성 응답 및 앱 검증 통과 (`source=gemini`) | 1.839초 |
| `gemini-2.5-flash` | HTTP 404, 기본 설명 반환 | 0.306초 |

404는 이번 키·API 경로에서의 결과이며 다른 환경의 지원 여부를 단정하지 않습니다. 성공 이력도 이후 가용성을 보장하지 않습니다. 기본값은 성공한 Lite로 변경했습니다.

## 통합 후 확인

1. 환경 변수가 설정된 배포에서 매장 계정으로 로그인하고 발주 페이지를 엽니다.
2. 클릭 전 기본 설명이 보이고, 성공 시 `Gemini AI 해설`이 표시되는지 확인합니다.
3. 수량 변경 시 기본 설명으로 돌아가며 새 수량·금액이 보이는지 확인합니다.
4. 키 없는 환경 또는 `GEMINI_ENABLED=0`에서 화면과 기본 설명이 유지되는지 확인합니다.
5. AI 해설은 발주 저장·확정과 별개입니다. 확정은 기존 팀 절차를 따릅니다.

## 검증

`web`에서 `npm test`, `npm run typecheck`, `npm run lint`를 실행합니다. 프로덕션 빌드는 `npm run build -- --webpack`으로 확인했습니다. 이 환경의 Turbopack은 호스트 포트 바인딩 제한 때문에 실패하여 Webpack으로 검증했습니다. 기존 빌드 스크립트와 Next 설정은 변경하지 않았습니다.
