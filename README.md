# 오늘의 발주 도우미 — 전처리·EDA·LLM 통합본

점장이 **무엇을 얼마나 발주하고, 어떤 재고부터 사용해야 하는지** 확인하는 프로토타입입니다.
기존 앱에 분석 데이터 생성, 검증, 운영 분석, OpenAI 발주 해설을 추가했습니다.

## 실행

Python 3.10 이상을 권장합니다. 이 작업에서는 Python 3.9 환경에서도 검증했습니다.

```bash
pip install -r requirements.txt
python pipeline.py
streamlit run app.py
```

분석 데이터는 이미 `analysis/`에 생성되어 있어 바로 앱을 실행할 수 있습니다.
CSV 교체 후에는 `python pipeline.py`를 다시 실행하고 앱을 재시작하세요.
원본 CSV를 임의로 수정하거나 중복행을 자동 삭제하지 않습니다. 오류가 있으면 검증 결과를 기록하고 실패로 종료합니다.

## OpenAI 연결

앱의 **발주 브리핑 → AI 연결 설정**에서 API 키를 입력하고 **AI 해설 생성 / 새로고침**을 누릅니다.
키는 파일이나 다운로드 보고서에 저장하지 않습니다. 브라우저 세션을 닫으면 세션 입력이 사라집니다.

배포 시에는 서버 환경변수 또는 `.streamlit/secrets.toml`에 설정하세요.

```toml
OPENAI_API_KEY = "여기에_실제_API_키"
OPENAI_MODEL = "gpt-4.1-mini"
```

실제 키가 담긴 파일은 저장소에 커밋하지 마세요. `.gitignore`에 제외해 두었습니다.
API가 없거나 오류가 나면 **계산 기반 기본 브리핑**을 표시합니다. 이를 AI 생성 결과라고 표시하지 않습니다.

버튼을 누를 때 선택 매장의 발주 계산 요약만 `https://api.openai.com/v1/responses`로 전송합니다.
원본 CSV 전체는 보내지 않습니다. `store=false`로 요청합니다.
LLM은 품목별 행동·근거를 쉬운 말로 설명하고 수량·금액·입고일은 코드의 값을 표시합니다.
응답의 품목 누락·중복·다른 ID와 설명 내 숫자를 검사합니다. 실제 이유의 타당성은 계산 근거와 함께 확인하세요.
수량·조건이 바뀌면 이전 해설을 재사용하지 않고 새 계산의 기본 브리핑으로 돌아갑니다.

## 시연

- 기본: `?store=S01&date=2026-10-01`
- 입고 전 부족: `?store=S02&date=2026-09-03`
- 최소 발주금액 대안: `?store=S03&date=2026-09-15`

아침 실사 반영으로 기존 앱과 일부 추천량은 달라질 수 있습니다.

## 검증

```bash
pip install pytest
python -m pytest tests -q
```

검증 대상: 원본 수지·집계, 취급 기간, 당일 제외 평균, 실사재고 복원, 행사 배수의 미래 참조 차단,
수량 수정 후 브리핑 갱신, API 응답 파싱, 잘못된 AI 응답 거부, 네트워크 오류 처리.
실제 API 호출은 유효한 사용자 API 키를 설정한 뒤 확인해야 합니다.

## 배포 담당자에게

앱 진입점은 `app.py`입니다. `engine.py`, `analytics_ui.py`, `briefing.py`, `data/`, `analysis/`를 함께 배포하세요.
배포 URL 제출은 별도 작업입니다. 이 폴더와 원본·파생 상세 데이터는 공개 저장소에 게시하지 마세요.
저장소를 비공개로 유지하고, 서비스 제공업체의 접근·공개 설정은 배포 담당자가 확인해야 합니다.
분석 페이지의 CSV 다운로드에는 파생 상세 데이터가 포함되므로 심사 범위에서 공유하세요.

공식 API 참고: https://developers.openai.com/api/docs/quickstart

합성 판매·재고 이력과 가상 금액을 사용했습니다. 실제 매장 성과나 비용 절감 실적으로 해석하지 않습니다.

## 최신 수정사항

- 보고서와 앱의 양상추 비교표에 소비기한 경과 폐기비용·발생 횟수 추가: A 0원·0회, B 63,192원·2회, C 105,134원·6회.
- 운영 반영 사항에 소비기한 경과 폐기가 B·C에만 발생했다는 설명 추가.
- 데이터 사전의 일반적인 설명 13개를 원본 파일·컬럼, 연결 방식, 단위로 구체화. 파이프라인 재실행에도 유지.
- PDF 보고서는 위 기준 데이터로 생성한 고정본입니다. CSV를 바꾸면 HTML은 pipeline.py로 갱신되지만 PDF는 별도로 다시 만들어야 합니다.
