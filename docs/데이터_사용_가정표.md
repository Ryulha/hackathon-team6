## 3. 추가한 가정
1. 리드타임은 달력일 기준, 도착일이 입고 가능 요일이 아니면 다음 입고 가능 요일로 밀린다.
2. 입고는 영업 시작 전 도착, 사용기한 당일까지 사용 가능, 이후 폐기.
3. 사용기한 빠른 묶음부터 사용(FEFO).
4. 예정일이 지난 미입고 발주분은 기준일에 도착한다.
5. 메뉴 취급 상태는 마지막 기록 이후에도 유지된다.
6. 데이터 이후 기간의 프로모션은 없다(사용자가 수요 조정으로 반영).

## 4. 반영하지 못한 조건
- 공휴일 효과, 채널별 수요 차이
- 발주 확정의 실제 공급사 연동 (모의 구현)

## 5. 직접 생성한 데이터 (제공 데이터와 구분)
- `pipeline/fixtures/*.csv`: 개발용 합성 데이터. **배포본에서는 사용하지 않음.**
- `agg_daily_demand`, `agg_daily_waste`: 제공 데이터를 합산한 집계 (새 값 생성 없음)
- `app_order_drafts`: 사용자가 저장한 발주안
